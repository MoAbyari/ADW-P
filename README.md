# AI Developer Workflow (ADW)

ADW turns a GitHub issue into a pull request. It classifies the issue as a chore, bug or
feature, writes an implementation plan, implements the plan, runs the project's validation
commands and opens a pull request. The work is done by [Claude Code](https://docs.anthropic.com/en/docs/claude-code).

This repository contains the workflow only, with no application attached. Add it to any
project that lives in a GitHub repository.

## Two Modes

ADW runs in two modes that share the same prompt templates in `.claude/commands/`:

| | Automated | Manual |
|---|---|---|
| Where it runs | GitHub Actions, through [GitHub Agentic Workflows](https://github.github.com/gh-aw/) | Your machine |
| How you start it | Comment a slash command on an issue or pull request | Run a script in `adws/` |
| Defined in | `.github/workflows/adw-*.md` | `adws/*.py` |
| Progress reporting | A start and finish status comment, plus one summary comment | A comment on the issue at every step |
| Pull request | Opened as a draft when the run finishes | Opened after the planning step |
| End-to-end tests | Skipped | Included |


## Add ADW to a Project

1. **Copy the files** into the root of your project: `.claude/`, `.github/`, `adws/`,
   `scripts/`, `specs/`, `.mcp.json`, `.env.sample` and `.gitattributes`. Add the entries
   from `.gitignore` to your own.

2. **Describe your project** in `.claude/adw_project.md`. It has four parts:

   | Section | What to put there |
   |---|---|
   | Relevant Files | The folders ADW should read and change |
   | Dependencies | How to add a library to the project |
   | Validation Commands | The commands that prove a change is safe: linter, tests, build |
   | Application | How to start, stop and reset the application, and its URL. Used by end-to-end tests. |

   The file ships with values that describe this repository, as a working example.

3. **For automated mode, describe the setup** in `.github/workflows/shared/adw-project.md`:
   the language runtimes to install, the package registries the agent may reach, and the
   commands that install dependencies. Then regenerate the workflows:

   ```bash
   gh aw compile --strict
   ```

4. **Commit everything to the default branch.** Slash commands only work once the
   workflows are on it.

## Manual Mode

Prerequisites:

- **GitHub CLI**: `brew install gh` (macOS) or equivalent for your OS
- **Claude Code CLI**: Install from [Claude Code documentation](https://docs.anthropic.com/en/docs/claude-code)
- **Python with uv**: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **GitHub authentication**: `gh auth login`

Environment variables:

```bash
export GITHUB_REPO_URL="https://github.com/owner/repository"
export ANTHROPIC_API_KEY="sk-ant-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
export CLAUDE_CODE_PATH="/path/to/claude"  # Optional, defaults to "claude"
export GITHUB_PAT="ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"  # Optional, only if using different account than 'gh auth login'
```

Check the setup, then process an issue:

```bash
uv run adws/adw_tests/health_check.py

cd adws/
uv run adw_plan_build.py <issue-number>        # Plan and implement
uv run adw_plan_build_test.py <issue-number>   # Plan, implement and test
```

See [`adws/README.md`](adws/README.md) for every script and option.

## Automated Mode

Write the command as the first word of an issue body or comment:

| Command | Where | Result |
|---|---|---|
| `/adw_plan` | Issue | Draft pull request containing the plan |
| `/adw_plan_build` | Issue | Draft pull request with the plan and implementation |
| `/adw_plan_build_test` | Issue | As above, plus the validation commands with automatic fixes |
| `/adw_build` | Pull request | Implements the plan and pushes to the pull request branch |
| `/adw_test` | Pull request | Runs the validation commands and pushes any fixes |

Only users with admin, maintainer or write access can trigger a run.

One-time setup:

```bash
gh extension install github/gh-aw --pin v0.89.21
gh aw secrets set ANTHROPIC_API_KEY
```

Then, in the repository settings under Actions > General, allow GitHub Actions to create
pull requests.

After changing the frontmatter of a workflow, run `gh aw compile --strict` and commit the
regenerated `.lock.yml` file. Changes to the prompt text below the frontmatter take effect
without recompiling.

## How ADW Works

1. **Issue Classification**: Analyzes the GitHub issue and determines its type (`/chore`, `/bug`, `/feature`)
2. **Planning**: Writes a detailed implementation plan to `specs/`
3. **Implementation**: Executes the plan by making code changes
4. **Validation**: Runs the project's validation commands and fixes what fails
5. **Integration**: Creates git commits and a pull request with semantic commit messages
